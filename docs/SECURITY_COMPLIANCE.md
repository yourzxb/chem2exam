# 安全与合规

## 1. 数据安全原则

- 学生数据按用户和班级权限隔离。
- 老师只能查看授权班级。
- 管理员权限应最小化分配。
- 敏感数据不得进入前端存储。
- 日志不得记录密码、API Key、学生隐私明文。

## 2. 密码安全

正式系统必须：

- 使用强哈希算法存储密码。
- 不得明文存储密码。
- 不得在日志中输出密码。
- 支持修改密码和重置密码流程。

## 3. API Key 安全

AI 模型 API Key 必须：

- 后端加密存储。
- 只在服务端调用时解密。
- 不返回给前端。
- 不写入普通日志。
- 不随导出数据泄漏。

管理端展示模型配置时，只能显示脱敏形式：

```text
sk-****abcd
```

## 4. 学生隐私

学生数据包括：

- 答题记录。
- 作答用时。
- 难度反馈。
- 行为评估。
- 学习报告。
- 奖励记录。

这些数据应仅用于学习诊断和教学改进，不应随意外传。

学校试点运营中，管理员可检索教师和学生账号以完成班级授权。该目录接口只能返回账号绑定所需的安全字段，不得返回密码哈希、会话凭证、模型密钥或学生学习明细。

## 5. 行为评估表达合规

系统内部可以有行为信号：

- possible_guessing。
- review_needed。
- thoughtful。
- fluent。

学生端不得直接显示：

- 乱做。
- 偷懒。
- 不认真。
- 低投入。

学生端应使用鼓励和行动建议。

## 6. 真题和解析版权

题库必须记录：

- 试卷来源。
- 年份。
- 地区。
- 上传人。
- 授权状态。
- 解析来源。

解析来源类型：

- 原解析。
- AI 生成。
- 老师改写。
- 人工审核。

商业化或公开分发前，应确认题目和解析授权。

## 7. AI 内容安全

AI 生成内容必须经过：

- 结构化校验。
- 人工审核。
- 发布状态控制。

AI 不能直接：

- 发布题目。
- 修改正式知识图谱。
- 覆盖人工审核结果。
- 给学生输出未经审核的正式解析。

## 8. 文件上传安全

后续支持试卷上传时必须考虑：

- 文件类型白名单。
- 文件大小限制。
- 病毒或恶意文件扫描。
- 私有存储。
- 下载权限校验。

## 9. 审计日志

以下操作应记录审计日志：

- 用户登录。
- 题目发布。
- 审核通过、修改、驳回。
- 知识图谱修改。
- AI 模型配置新增或修改。
- API Key 更新。
- 权限变更。

审计日志应记录：

- 操作人。
- 操作时间。
- 操作对象。
- 操作类型。
- 修改前后摘要。

## 10. 最小权限原则

- 学生无审核权限。
- 老师只能审核被授权范围内的题目。
- 管理员才能配置 AI 模型。
- 普通老师不应看到 API Key。
