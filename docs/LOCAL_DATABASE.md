# 本地数据库启动说明

本项目使用 PostgreSQL + Prisma。

## 1. 环境变量

复制 `.env.example` 为 `.env`，默认内容如下：

```text
DATABASE_URL="postgresql://chem2exam:chem2exam@localhost:5432/chem2exam?schema=public"
AUTH_SECRET="replace-with-a-long-random-secret"
```

## 2. 使用 Docker 启动 PostgreSQL

先确保 Docker Desktop 已启动，然后执行：

```bash
docker compose up -d postgres
```

## 3. 推送数据库结构

```bash
npm run db:push
```

## 4. 导入种子数据

```bash
npm run db:seed
```

种子数据包括：

- 初三、高一、高二、高三示例知识点。
- 前置依赖和上下级关系。
- 已发布的真题式示例题。
- 题目知识点挂接。
- 核心素养标签。
- 演示学生、老师和管理员账号。
- 示范班级绑定、学生作答、错题复盘任务和成长奖励数据。

演示账号：

| 角色 | 用户名 | 登录口令 |
| --- | --- | --- |
| 学生 | `demo_student_01` | `Chem2Exam@2026` |
| 老师 | `demo_teacher` | `Chem2Exam@2026` |
| 管理员 / 审核员 | `demo_admin` | `Chem2Exam@2026` |

## 5. 开发回退机制

如果没有配置 `DATABASE_URL`，系统会自动使用内存/种子数据仓库，方便本地构建和页面开发。

配置 `DATABASE_URL` 后：

- 注册登录优先使用 Prisma `User` 表。
- 学习仓库优先使用 Prisma 知识图谱和题库表。

## 6. 数据库流程验证

如果只是想确认本地项目整体是否能跑通，可直接执行：

```bash
npm run verify:all
```

该命令会自动执行数据库准备、类型检查、业务测试、生产构建，并启动或复用 `4174` 端口服务来跑页面冒烟、演示账号登录、学生端、审核端、老师端和管理端验证脚本。

验证演示账号登录链路：

```bash
npm run verify:demo-login
```

该脚本验证学生、老师、管理员和审核员演示账号可登录，并能访问各自权限范围内的基础接口。执行前需先导入种子数据并启动本地服务。

先启动本地 Next.js 服务：

```bash
npm run dev -- -p 4174
```

验证学生学习写入链路：

```bash
npm run verify:db-flow
```

该脚本验证：

- 学生注册和登录 Cookie。
- 答题记录写入。
- 错后补救路径写入。
- 成长奖励写入。
- 学生报告和排行榜读取真实数据。

验证审核和整卷拆题链路：

```bash
npm run verify:review-flow
```

该脚本验证：

- 管理员注册。
- AI 模型配置保存且不返回 API Key 明文。
- 整卷拆题生成待审核候选题。
- 审核队列按题型、知识点、置信度筛选。
- 低置信度题批量转为需修改。
- 待审题请求 AI 重新分析。
- 审核历史返回变更摘要和关联 AI 任务。
- 一审通过后题目状态变为 published。

验证老师端班级报告链路：

```bash
npm run verify:teacher-flow
```

该脚本验证：

- 学生作答数据写入。
- 老师账号读取班级报告。
- 报告返回薄弱知识点、题型错题讲评和核心素养讲评。
- 综合讲评建议包含核心素养维度。
- 报告支持按年级和时间范围筛选，并会回显本次筛选条件。
- 报告支持 CSV 导出。
- 老师可按知识点下钻查看相关学生名单和讲评建议。
- 老师可按学生下钻查看个人错题清单和下一步复盘建议。
- 老师可导出学生错题清单 CSV。
- 老师可为学生分配错题复盘任务，任务会写入补救路径记录。
- 学生可在学习报告中看到老师分配的错题复盘任务。
- 学生完成复盘任务后会写入 `completed_review:<teacherId>` 状态、学生复盘笔记和 `review_completed` 奖励。
- 老师再次查看学生详情时可看到复盘任务待完成/已完成反馈和学生复盘笔记。
- 老师可按复盘状态筛选学生列表，学生端可从复盘任务进入同类题复测入口。
- 老师可对待完成复盘任务生成温和提醒记录，系统会保存提醒次数和最近提醒时间。
- 学生从复盘任务进入同类题复测并提交答案后，复测题目、作答记录、正确性和完成时间会回写到该复盘任务。
- 学生端会根据同类题复测结果展示下一步行动，做对后进入变式题挑战，还需巩固时回到前置知识或基础同类题。
- 学生继续完成变式题挑战或前置知识巩固后，会写入对应成长奖励，并在复盘任务中展示下一步状态。
- 学生报告会把复盘任务整理为今日任务、已完成任务和成长轨迹，帮助学生看到下一步和累计成长。
- 学生报告会生成本周成长摘要和核心素养成长摘要，帮助学生看到最近 7 天的成长行为和化学能力维度积累。
- 学生报告会生成按周成长回顾卡片、核心素养目标和阶段性鼓励徽章。
- 学生可选择一个核心素养目标，目标保存到 `StudentLearningGoal`，再次读取报告时会回显。
- 学生选择核心素养目标后，系统会根据后续相关作答自动完成目标，写入 `literacy_progress` 奖励，并在报告中显示完成历史。
- 老师可批量提醒多名学生，系统会按冷却时间跳过短时间内重复提醒的任务。
- 老师可按已提醒、待提醒和提醒冷却中筛选学生。
- 老师班级报告会按同类题复测结果汇总“已迁移成功 / 继续巩固中 / 待复测”，并在学生摘要中给出个人建议。
- 老师可按同类题复测结果筛选学生，快速定位已迁移成功、继续巩固中、待复测和暂无复测任务的学生。
- 老师班级报告会展示最近 7 天复盘推进趋势，并按继续巩固、待复测、可挑战变式和需要分配复盘生成分层建议。
- 老师可按分层复盘建议筛选学生，并导出当前口径下的复盘跟进名单 CSV。
- 老师可基于复盘跟进名单批量分配下一轮变式题挑战或前置知识巩固任务。
- 老师班级报告会统计下一轮变式题挑战和前置知识巩固任务的待完成、已完成和完成率。
- 老师可按任务类型筛选学生，定位变式题挑战或前置知识巩固的跟进名单。
- 老师班级报告会在下一轮任务汇总中列出待完成学生和已完成学生，复盘跟进 CSV 会导出任务类型明细。
- 老师可为已完成的复盘或二次任务保存评价备注，班级报告、学生详情和复盘跟进 CSV 会显示完成反馈、课堂讲评建议和老师备注数。
- 老师可按老师备注状态筛选学生，导出已有备注的讲评素材或待写备注的跟进名单。
- 老师班级报告和复盘跟进 CSV 会包含“老师备注讲评清单”，用于课堂讲评准备。

验证管理端题库维护链路：

```bash
npm run verify:admin-flow
```

该脚本验证：

- 管理员账号可以维护题目元数据。
- 管理员可以修改审核状态、题型、人工难度和中位用时。
- 管理员可以修改答案、解析和核心素养标签。
- 管理员可以把题目重新挂接到人工确认的主知识点。
- 管理员可以按题型、年级和主知识点筛选题库。
- 系统会写入 `admin_update_question` 审核记录。
- 管理员可以批量修改题目审核状态、难度、主知识点挂接和核心素养标签，并写入 `admin_batch_update_question` 审核记录。
- 管理端题库筛选条件会在本地保存，刷新页面后保留筛选口径。
- 管理端支持命名保存多个筛选方案，并在批量更新前展示操作预览。
- 管理端支持将筛选方案导出/导入为本地 JSON，不经过后端接口。
- 管理端批量更新前必须勾选二次确认，降低误改审核状态和知识点挂接的风险。
- 被改为 `needs_edit` 的题目不会出现在学生练习接口中。
- 管理端可通过安全账号目录检索教师和学生，结果不返回敏感凭证字段。
- 管理端可批量将多个学生加入班级，非学生账号和未找到账号会被跳过，成功入班会写入组织审计。

## 7. 当前注意事项

- 本机如果没有启动 Docker daemon，`docker compose up -d postgres` 会失败。
- 当前还没有自动创建 `.env`，需要手动从 `.env.example` 复制。
