# MVP 详细规格

## 1. MVP 目标

MVP 只验证最关键的学习闭环：

```text
学生做真题
→ 系统发现知识断点
→ 给出错后学习导航
→ 学生补前置知识
→ 回到原知识点复测
→ 生成简要学习报告
```

MVP 不追求完整 AI 整卷拆题和复杂老师端，但必须为后续扩展留下数据结构和审核状态。

## 2. MVP 必做范围

### 2.1 学生账号

必须支持：

- 学生注册。
- 学生登录。
- 学生退出。
- 每个学生保留独立学习记录。

验收：

- A 学生和 B 学生的答题记录、奖励和报告互不混淆。

### 2.2 年级和知识图谱

必须支持：

- 初三、高一、高二、高三。
- 每个年级至少一张知识图谱。
- 节点展示状态：未测试、待巩固、已掌握。
- 知识点关系至少支持 parent 和 prerequisite。

验收：

- 学生选择不同年级后，知识图谱和题目范围随之改变。
- 答错后优先根据 prerequisite 推荐补救节点。

### 2.3 真题式题库

MVP 可以先使用人工录入或内置示例题，但题目必须具备正式字段：

- 题干。
- 选项。
- 答案。
- 解析。
- 年级。
- 难度。
- 主知识点。
- 前置知识点。
- 核心素养标签。
- 审核状态。
- 发布状态。

验收：

- 学生端只显示 auditStatus 为 published 的题目。
- 未发布题目不得进入学生练习。

### 2.4 做题诊断

必须记录：

- 开始作答时间。
- 提交时间。
- 用时。
- 学生答案。
- 正确与否。
- 所属知识点。
- 学生主观难度反馈。

验收：

- 每次作答产生一条答题记录。
- 作答记录可用于生成学习报告。

### 2.5 错后学习导航

答错后必须显示：

- 错因提示。
- 推荐前置知识点。
- 一句关键知识提示。
- 下一步路径。
- 鼓励语。

验收：

- 答错后不能只显示“答案错误”。
- 页面必须明确告诉学生先学什么、做什么、如何回来复测。

### 2.6 补救和复测

必须支持：

- 从错题进入前置知识点补救。
- 完成前置补救后回到原知识点。
- 原错题或同类题复测。

验收：

- 学生从知识点 A 出错，进入知识点 B 补救，完成后回到 A。
- 系统记录该次补救路径。

### 2.7 时间评估

MVP 可先使用预设中位数。

时间区间：

- 小于中位数 25%：过快。
- 25%-70%：较快。
- 70%-150%：正常。
- 150%-250%：较慢。
- 大于 250%：卡顿。

验收：

- 系统根据用时生成内部 timeAssessment。
- 学生端用温和表达，不出现负面标签。

### 2.8 学生难度反馈

每题完成后支持：

- 容易。
- 中等。
- 难。

验收：

- 学生反馈保存到答题记录。
- 后续推荐可读取该反馈。

### 2.9 成长型奖励

MVP 奖励重点：

- 连续学习。
- 完成补救路径。
- 完成错题复盘。
- 从“难”到“会”。
- 核心素养维度进步。

低权重奖励：

- 单题答对。

验收：

- 完成补救路径获得奖励高于答对一道普通基础题。
- 答错但完成复盘也能获得奖励。

### 2.10 简要学习报告

学生报告包括：

- 本次做题数量。
- 正确率。
- 薄弱知识点。
- 已补救知识点。
- 认真思考或过快作答提示。
- 核心素养表现。
- 下一步建议。

验收：

- 学生完成一次测试后能看到报告。
- 报告包含至少一条下一步学习建议。

### 2.11 排行榜

MVP 可选支持排行榜。如果实现，应先做成长型排行榜，而不是刷题数量榜。

优先支持：

- 本周成长积分榜。
- 个人历史最佳。

计分重点：

- 完成补救路径。
- 完成错题复盘。
- 从“难”到“会”。
- 连续学习。

验收：

- 学生能看到自己的本周排名。
- 排行榜不以单纯答题数量为主要依据。
- 学生端不显示负面排名文案。

## 3. MVP 不做范围

MVP 暂不做：

- 整卷 PDF 上传。
- AI 自动拆题。
- AI 模型配置中心。
- 完整老师端班级看板。
- 多学校组织架构。
- 复杂支付和商业化功能。
- 多学科扩展。

但数据模型和代码结构要为这些功能预留扩展空间。

## 4. MVP 页面清单

学生端：

- 登录 / 注册页。
- 年级选择和学习首页。
- 知识图谱页。
- 做题页。
- 错后学习导航页或面板。
- 补救学习页。
- 学习报告页。
- 排行榜页或排行榜面板。

管理占位：

- 题库列表页。
- 知识点管理页。
- 审核状态字段。

MVP 可以先不实现完整管理端，但不得在数据设计中省略审核和发布状态。

## 5. MVP 成功指标

产品指标：

- 学生能清楚知道做错后下一步学什么。
- 学生能完成至少一次“错题 → 补救 → 复测”。
- 学生端反馈温和且有行动建议。

技术指标：

- 核心数据可持久化。
- 题目状态能区分未审核和已发布。
- 作答记录包含时间、结果、反馈和补救状态。
