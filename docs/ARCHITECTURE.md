# 技术架构文档

## 1. 架构目标

系统应支持从静态演示版逐步演进为可运营的三端平台：

- 学生端：诊断学习、错后补救、奖励和报告。
- 老师端：班级诊断、题目审核、练习布置。
- 管理端：知识图谱、题库、AI 模型和权限管理。

架构必须保证：

- 学生端只能访问已审核并发布的内容。
- AI 结果必须进入人工审核流程。
- API Key 和模型配置只存在后端安全环境。
- 知识图谱、题库和学生记录可长期迭代。

## 2. 推荐技术栈

后续正式系统建议：

- 前端：React + TypeScript + Vite 或 Next.js。
- 后端：Node.js/NestJS、Python/FastAPI 或其他团队熟悉的后端框架。
- 数据库：PostgreSQL。
- 缓存与队列：Redis。
- 文件存储：本地对象存储、MinIO 或云对象存储。
- AI 调用：后端统一 AI Gateway。
- 权限：RBAC 角色权限模型。

当前仓库已有静态原型，后续迁移时应保留核心业务规则，不应将原型代码直接当作最终架构。

## 3. 模块划分

### 3.1 学生学习模块

- 年级选择。
- 知识图谱展示。
- 题目作答。
- 时间统计。
- 难度反馈。
- 错后学习导航。
- 奖励和头像反馈。
- 学习报告。

### 3.2 知识图谱模块

- 知识点 CRUD。
- 知识点关系管理。
- 图谱版本管理。
- 节点题量统计。
- 节点掌握状态计算。

知识点关系类型：

- parent：上下级。
- prerequisite：前置依赖。
- confused_with：易混淆。
- similar_practice：同类巩固。
- integrated_application：综合应用。

### 3.3 题库模块

- 试卷管理。
- 题目管理。
- 答案和解析管理。
- 来源和版权管理。
- 题目发布状态管理。

### 3.4 AI 能力中心

- 模型供应商配置。
- API Key 加密存储。
- 任务级模型路由。
- 默认模型和备用模型。
- AI 任务队列。
- 结构化输出校验。
- 调用日志和费用统计。

### 3.5 审核模块

- 待审核题目列表。
- 逐题审核。
- 高置信度批量通过。
- 修改后通过。
- 驳回。
- 重新 AI 分析。
- 审核记录。

### 3.6 老师看板模块

- 班级知识点热力图。
- 学生个人报告。
- 核心素养画像。
- 错题和薄弱点分析。
- 推荐讲评题和分层作业。

## 4. 内容发布原则

正式题库内容必须经过以下流程：

```text
AI 生成候选结果
→ 人工审核
→ 发布
→ 学生端可见
```

严禁：

- 未审核题目进入学生端。
- AI 结果自动覆盖人工审核结果。
- 学生端调用大模型生成正式答案或挂接结果。

## 5. AI 后台任务流

```text
创建 AI 任务
→ 进入队列
→ 读取任务类型对应模型配置
→ 调用默认模型
→ 失败时按规则重试或切备用模型
→ 校验 JSON 输出
→ 保存候选结果
→ 进入人工审核
```

任务状态：

- pending：等待中。
- running：处理中。
- succeeded：已完成。
- failed：失败。
- needs_review：需人工处理。

## 6. 权限模型

基础角色：

- student：学生。
- teacher：老师。
- admin：管理员。

关键权限：

- view_published_questions。
- submit_answers。
- view_student_reports。
- upload_exam_papers。
- review_questions。
- publish_questions。
- manage_knowledge_graph。
- manage_ai_models。
- manage_users。

## 7. 数据隔离原则

- 学生只能读取自己的答题记录和学习报告。
- 老师只能读取授权班级的学生数据。
- 管理员可管理全局配置。
- API Key 不得出现在前端、日志明文、浏览器存储或导出文件中。
- 学生登录状态使用后端签名的 httpOnly Cookie；前端不能自行决定当前学生身份。

## 8. 版本管理

必须考虑：

- 知识图谱版本。
- 题目挂接版本。
- 题目内容版本。
- AI 推荐版本。
- 审核修改记录。

学生历史答题记录应指向当时使用的题目版本和知识图谱版本，避免后续图谱调整导致历史报告失真。

## 9. 可观测性

后端应记录：

- AI 任务状态。
- 模型调用耗时。
- token 或费用消耗。
- 失败原因。
- 审核操作。
- 发布操作。
- 学生作答事件。

日志中不得记录 API Key 明文。
